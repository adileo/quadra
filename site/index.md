<div class="q-proof__text">
<div class="q-proof__n">Quadra</div>

### Write only the rules. The app builds itself as you save.

Write your data structure, your rules and your automations, all in one simple language that anyone can audit. Even AI can audit and write it.

</div>
<div class="q-proof__code">

<Fold>

```quadra
entity Customer:
    name: Text
    orders: [Order] via customer

entity Product:
    name: Text
    cost: Money<EUR>
    price: Money<EUR>
    stock: Int where >= 0

entity Order:
    customer: Customer
    date: Date default today()
    lines: [OrderLine]
    state: enum(Draft, Confirmed, Shipped) default Draft

    revenue = lines.sum(l => l.amount)
    margin = lines.sum(l => l.margin)

    flow state:
        Draft -> Confirmed by confirm
        Confirmed -> Shipped by ship

    action confirm:
        require margin > 0, "Below cost: this order loses money"

    action ship:
        for l in lines:
            l.product.stock = l.product.stock - l.qty

entity OrderLine:
    order: Order parent
    product: Product
    qty: Int where > 0 default 1

    amount = product.price * qty
    margin = (product.price - product.cost) * qty

    check qty <= product.stock, "Not enough stock"
```

</Fold>

<div class="q-proof__n">Permissions and Sign-in</div>

### Who sees what, and who does what, written as code

Roles, rules and hidden fields live in the model, next to the data. They apply everywhere: in the app, in the API and inside every action. Sign-in with a code sent by email and API tokens are already built in.

</div>
<div class="q-proof__code">

```quadra
role Sales:
    read Customer, Product
    read, edit Order where o => o.created_by == me
    run Order.confirm where o => o.created_by == me
    hide Product.cost

role Warehouse:
    read Order, Product
    run Order.ship

role Manager is Sales:
    read, edit Order
    show Product.cost
```

<div class="q-proof__n">Audit and History</div>

### An audit trail you don’t have to build

Every value ever written is kept, with who changed it, when and why. The history is chained by hashes, so altering the past is detected. Ledgers are append-only, confirmed documents are frozen, and a bulk change needs the approval of a second person: the guarantees finance and compliance ask for, from day one.

<div class="q-proof">
<div class="q-proof__text">
<div class="q-proof__n">Certified Metrics</div>

### One definition of margin, for the whole company

Ask three departments for the margin and you get three numbers: one counts drafts, one forgets returns, one uses last year’s costs. In Quadra a metric is defined once, with an owner and a definition in plain words, and every report uses the same one.

It is certified: if a change anywhere in the model alters what it means, even a default far away, `quadra check` stops until it is approved again.

</div>
<div class="q-proof__code">

```quadra
metric gross_margin(period: DateRange) -> Money<EUR>:
    label: "Gross margin"
    owner: "Finance"
    definition: "Price minus cost of shipped orders."
    value = Order
        .where(o => o.state is Shipped and o.date in period)
        .sum(o => o.margin)
```

<pre class="q-term"><span class="c">$ quadra certify gross_margin --approved-by "m.bianchi (CFO)"</span>
<span class="ok">certified gross_margin: sha256:a1c018754ce6c703 (9 dependencies)</span></pre>

<ol class="q-safe__steps q-safe__steps--3">
  <li><b>Defined once</b><span>dashboards show it with a certified mark</span></li>
